# Casa Raíz PageSpeed 100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Casa Raíz production landing page repeatedly score 100/100 for Lighthouse/PageSpeed Performance, Accessibility, Best Practices, and SEO on mobile and desktop without changing the restaurant’s visual identity or current interaction behavior.

**Architecture:** Keep the Vite/React SPA and current GSAP experience. Remove the largest critical-path costs first (remote blocking fonts and oversized media), repair Lighthouse accessibility failures, then split only the JavaScript that measurements prove is unnecessary on first paint. Verify every stage with existing tests plus matched Lighthouse runs; revert neutral or negative optimizations.

**Tech Stack:** React 19, Vite 7, GSAP 3, Lenis, Vitest, Playwright, Vercel.

## Global Constraints

- Preserve the current design, copy, typography appearance, custom cursor, plate modal, House-menu previews, drinks interactions, CTA motion, language transitions, reduced-motion behavior, desktop Lenis behavior, mobile Lenis-free internal navigation, and the new smooth mobile hamburger-menu animation.
- Slightly darkening muted text is approved only where needed for WCAG contrast.
- Do not weaken, skip, or delete existing tests to make an optimization pass.
- Keep a performance change only when matched measurements are meaningfully better; revert neutral or negative changes.
- CrUX currently reports no field data for this URL; never substitute Lighthouse lab data for RUM.
- No remote push until final local verification is complete.
